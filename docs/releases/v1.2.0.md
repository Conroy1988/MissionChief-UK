## Operational metadata contracts

The release adds lossless canonical contracts for official information that must not be reduced to ordinary vehicle quantities, including:

- mission generator families and service identity;
- base mission, overlay and generated-variant metadata;
- mission relationships with published multiplicity preserved;
- seasonal and date-bounded availability;
- published duration and custom spawn-area behaviour;
- building-family and maximum-station generation rules;
- minimum pumping-speed and water-volume thresholds;
- mission flags, handoff rules, vehicle groups and personnel averages;
- mountain rescue, coastguard, flood response, aviation and bomb-disposal capabilities; and
- heavy recovery ranges, including the explicitly evidenced zero-minimum default where the source publishes only a maximum.

Unknown semantics are not guessed. Each retained field is either translated through an evidence-backed mapping or preserved within `official_metadata`.

## Deterministic generation

`scripts/generate_full_canonical_catalogue.py` reproduces all 1,062 direct canonical records, Batch 31 and its evidence page from the retained official snapshot and verified mapping registries.

The check mode fails when any committed generated output drifts. Collision-safe paths are generated for duplicate mission names and slash-qualified official IDs.

## Validation

Every promoted mission is subject to:

1. exact official identity validation;
2. strict resource, chance and prerequisite equivalence;
3. patient equivalence;
4. mapped personnel and personnel-education equivalence;
5. prisoner equivalence;
6. recovery-outcome equivalence;
7. conditional-resource equivalence;
8. complete operational-metadata equivalence; and
9. deterministic full-catalogue regeneration.

The full release pipeline also requires canonical schema validation, catalogue losslessness, zero unmapped-key backlog, generated-publication cleanliness, link and anchor auditing, strict MkDocs builds, JavaScript validation and cross-browser acceptance.

## Compatibility

The public v1 API structure remains compatible. Version metadata advances to `1.2.0`, and generated exports now expose the completed catalogue and expanded verified resource collections.
