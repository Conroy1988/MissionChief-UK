# Strategy Command Centre

Strategy pages convert verified mechanics and the completed service guides into practical planning models. Recommendations state their assumptions and are never presented as immutable game rules.

## Operating sequence

1. Verify current mission pressure in [Mission Lookup](../tools/mission-lookup.md).
2. Identify the narrowest quantity, geography, personnel, command or throughput deficit.
3. Review the relevant [service guide](../services/index.md).
4. Compare candidate resources using [Resource Comparison](../tools/resource-comparison.md).
5. Test overlap in the [Concurrent Fleet Planner](../tools/fleet-planner.md).
6. Preserve routine and specialist reserve.
7. Activate one controlled expansion.
8. Observe the changed mission mix and recover to Ready before repeating.
9. Use alliance support as documented contingency rather than an unbounded substitute for local capability.

## Strategy pillars

| Pillar | Planning question |
|---|---|
| Readiness | Can the current network handle its representative incidents with reserve? |
| Evidence | Is the proposed capability backed by current canonical mission pressure? |
| Geography | Will the resource reach its intended incidents, access points and destinations? |
| Personnel | Are the required qualifications and roles concurrently available? |
| Cross-service integration | Are every hard partner service and handoff ready? |
| Throughput | Can patients, prisoners, recovery assets and returning vehicles complete the full cycle? |
| Resilience | Can another incident occur without regional collapse? |
| Alliance contingency | Can support be requested without emptying donor networks or hiding local gaps? |
| Recovery | Does the network return to useful positions before more generation activates? |

## Account models

### Foundation

- routine Fire, Police and Ambulance response;
- useful local reserve;
- practical station geography;
- first specialists commissioned only against measured demand.

### Developing

- independently functional response clusters;
- trained specialist and replacement cohorts;
- patient, custody and recovery throughput measured;
- command and support no longer single points of failure.

### Regional

- service specialisation aligned with cross-service dependencies;
- relief bases and strategic reserve;
- urban, rural, coastal, airport and railway geography treated explicitly;
- several representative incidents tested together.

### Mature

- independently dispatchable regions;
- major-incident and recovery doctrine;
- alliance support used as contingency;
- new game content enters through the evidence workflow rather than assumptions.

## Strategy boundaries

The strategy programme does not:

- invent universal unlock thresholds;
- turn missing costs or capacities into zero;
- assume every account should buy services in one fixed order;
- merge guaranteed, alternative, conditional or probabilistic requirements;
- convert patient, prisoner or recovery ranges into fictional resource rows;
- treat alliance support as guaranteed local capacity;
- present community administration policies as game-enforced mechanics;
- optimise only for visual map symmetry.
